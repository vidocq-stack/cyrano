= Cyrano
:description: MicroProfile Rest Client 4.0 for Vidocq — type-safe REST clients with zero third-party dependencies.

[.lead]
Cyrano is the Vidocq implementation of MicroProfile Rest Client 4.0: you declare a Java
interface annotated with JAX-RS annotations, and Cyrano calls the remote service on its
behalf. It builds on xref:cassini::index.adoc[Cassini] (JAX-RS types) and is wired into
the runtime through xref:vidocq::index.adoc[Vidocq], with zero third-party libraries.

== Origin of the name

Cyrano de Bergerac (1619–1655) spoke on behalf of others, lending them his eloquence to
reach those they could not win over alone. That is exactly what a type-safe REST client
does: it speaks on behalf of the application code, lending it proxies and annotations to
call remote services without the caller having to know the underlying protocol or
transport.

== Interface-typed clients

A REST client is a plain Java interface annotated with `@RegisterRestClient` plus the
familiar JAX-RS annotations (`@Path`, `@GET`/`@POST`/`@PUT`/`@DELETE`/`@PATCH`,
`@PathParam`, `@QueryParam`, `@HeaderParam`, `@CookieParam`, `@ClientHeaderParam`,
`@FormParam`, `@BeanParam`, `@Consumes`, `@Produces`). Methods can return primitives and
their wrappers, `String`, `jakarta.ws.rs.core.Response`, JSON-B-deserialized POJOs,
`Optional<T>`, `List<T>`, `Set<T>`, `Map<K,V>`, and `CompletionStage<T>` for non-blocking
calls completed on a virtual thread. JSON serialization goes through Champollion (Jakarta
JSON-B); the HTTP transport is the JDK `java.net.http.HttpClient` running on a
virtual-thread executor.

== Proxy generation via Class-File API

Instead of `java.lang.reflect.Proxy`, Cyrano generates a real named class
`Cyrano$<InterfaceName>` on first use through the JDK 25 Class-File API (JEP 484), loaded
with `MethodHandles.Lookup.defineClass` and cached by `CyranoProxyCache`. There is no
ASM/Byte Buddy dependency and no `setAccessible(true)`, which keeps the result compatible
with AOT (GraalVM `native-image`, Leyden CDS) and produces readable stack traces.

== Integration

`cyrano-core` is standalone and depends only on `jakarta.ws.rs` and `jakarta.json.bind`
(transport via the JDK `HttpClient`). `cyrano-cdi-vauban` adds CDI integration: a Vauban
BuildCompatibleExtension discovers `@RegisterRestClient` interfaces and exposes them as
`@RestClient`-qualified beans for `@Inject`, with the base URI resolved from the
annotation or from MicroProfile Config (Ravel) via the `<configKey>/mp-rest/url` and
`<interface.fqn>/mp-rest/url` keys.

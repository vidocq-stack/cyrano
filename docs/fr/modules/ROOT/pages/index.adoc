= Cyrano
:description: MicroProfile Rest Client 4.0 pour Vidocq — clients REST typés, zéro dépendance tierce.

[.lead]
Cyrano est l'implémentation Vidocq de MicroProfile Rest Client 4.0 : vous déclarez une
interface Java annotée avec les annotations JAX-RS, et Cyrano appelle le service distant
en son nom. Il s'appuie sur xref:cassini::index.adoc[Cassini] (types JAX-RS) et s'intègre
au runtime via xref:vidocq::index.adoc[Vidocq], sans aucune librairie tierce.

== Origine du nom

Cyrano de Bergerac (1619–1655) parlait au nom des autres, leur prêtant son éloquence pour
séduire qui ils ne pouvaient atteindre seuls. C'est exactement ce que fait un client REST
typé : il parle au nom du code applicatif, lui prêtant ses proxies et ses annotations pour
appeler les services distants sans que l'appelant ait à connaître le protocole ou le
transport sous-jacent.

== Clients typés par interface

Un client REST est une simple interface Java annotée `@RegisterRestClient` plus les
annotations JAX-RS habituelles (`@Path`, `@GET`/`@POST`/`@PUT`/`@DELETE`/`@PATCH`,
`@PathParam`, `@QueryParam`, `@HeaderParam`, `@CookieParam`, `@ClientHeaderParam`,
`@FormParam`, `@BeanParam`, `@Consumes`, `@Produces`). Les méthodes peuvent retourner les
types primitifs et leurs wrappers, `String`, `jakarta.ws.rs.core.Response`, des POJO
désérialisés via JSON-B, `Optional<T>`, `List<T>`, `Set<T>`, `Map<K,V>`, ainsi que
`CompletionStage<T>` pour les appels non-bloquants complétés sur un virtual thread. La
sérialisation JSON passe par Champollion (Jakarta JSON-B) ; le transport HTTP est le
`java.net.http.HttpClient` du JDK exécuté sur un executor de virtual threads.

== Génération de proxy via Class-File API

Au lieu de `java.lang.reflect.Proxy`, Cyrano génère à la première utilisation une vraie
classe nommée `Cyrano$<NomInterface>` via la Class-File API du JDK 25 (JEP 484), chargée
avec `MethodHandles.Lookup.defineClass` et mise en cache par `CyranoProxyCache`. Aucune
dépendance ASM/Byte Buddy, pas de `setAccessible(true)`, ce qui garde le résultat
compatible AOT (GraalVM `native-image`, Leyden CDS) et produit des stack traces lisibles.

== Intégration

`cyrano-core` est standalone et ne dépend que de `jakarta.ws.rs` et `jakarta.json.bind`
(transport via le `HttpClient` du JDK). `cyrano-cdi-vauban` ajoute l'intégration CDI : une
BuildCompatibleExtension Vauban découvre les interfaces `@RegisterRestClient` et les expose
en tant que beans qualifiés `@RestClient` pour `@Inject`, la base URI étant résolue depuis
l'annotation ou depuis MicroProfile Config (Ravel) via les clés `<configKey>/mp-rest/url`
et `<interface.fqn>/mp-rest/url`.
